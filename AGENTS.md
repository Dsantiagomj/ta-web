# Agent contract for torrente-arcano

Rules for any agent that changes this repo. It is the new torrentearcano.com: Torre's Dofus quest guides, achievements, classes, Dofus guides and checklists, with member accounts, per-member progress and premium features. It replaces the Squarespace site and the embeds served from `silvestre-checklist`. The plan, decisions and phases are in `docs/plan.md`; visual rules are in `DESIGN.md`.

The app skeleton exists: Next.js with Payload, the design tokens, the test suites, the git hooks and CI. Most of the rest is **planned**. When a rule names a path or command that does not exist yet, create it that way. How to run it locally is in the Development section of `README.md`.

## When this applies

Every change: code, content model, migrations, data, docs, CI. Read this file before the first edit. For UI work read `DESIGN.md` too.

## Quick path

1. One branch per change, in a worktree under `../torrente-arcano-worktrees/<name>`.
2. Strict TDD: write or adjust the test, watch it fail, then implement.
3. Schema change: generate and commit the migration in the same branch.
4. Run every suite locally (see Testing). Report failures verbatim. The pre-commit hook runs Prettier, ESLint and the `gga` review on staged files; do not skip it (`--no-verify`, `LEFTHOOK=0`, `LEFTHOOK_EXCLUDE`) unless the user asks.
5. UI change: screenshots at 1440, 1024 and 390 px, Arcano dark and light (plus any theme the change touches), in `tmp/shots/`, next to the approved mockup.
6. Open the PR: conventional commit title, Spanish body. No auto-merge unless asked.

## Strict TDD

1. Write the test (or change the assertion) first. Run it and watch it fail for the right reason.
2. Implement the smallest change that passes.
3. Run the suite the test belongs to, then every suite before pushing.
4. A refactor PR never edits assertions.

The `localStorage` try/catch rule and the imagery rules (`DESIGN.md`, Imagery) apply to app code. Tests may touch storage directly if they handle the failure with a clear message.

Access control and entitlements are tested at the data layer: a test calls the Payload local API as an anonymous user, a free member and a premium member, and asserts what each one receives.

## Testing

| Suite | Command | Covers |
|---|---|---|
| Unit | `pnpm test` (Vitest) | `src/lib/` (progress merge, entitlements, derived data, media URLs), collection access functions, hooks |
| E2E | `pnpm test:e2e` (Playwright on the production path: `pnpm build`, `pnpm migrate` on an empty database, `pnpm start`) | rendered pages against a seeded database: guides, checklists, search, theme, sign-in, progress, premium gating; the suites ported from `silvestre-checklist` in phase 2a |
| Smoke | `pnpm test:smoke` (the `@smoke` Playwright subset; `SMOKE_BASE_URL` points it at a deployed URL and skips the local server) | read-only checks after a deploy: home renders, `/admin` responds, `/api/health` is ok. `.github/workflows/smoke.yml` runs it against a URL; deploys will call it. Smoke tests never write data |
| Budgets (planned) | `pnpm test:lhci` (Lighthouse CI) | the budgets in `DESIGN.md` on a fixed set of pages (home, a quest guide, an achievement, a checklist) |
| Types, lint and format | `pnpm typecheck`, `pnpm lint`, `pnpm format:check` | the whole repo |
| Import (planned) | `pnpm test:import` | golden pages of the Squarespace import (phase 1) |

CI (`.github/workflows/ci.yml`) runs lint, types, unit, build and E2E on every PR and push to `main`; the `Pruebas` job requires all of them. Budgets and import join when they exist. The `Revisión GGA` job reviews the PR with `gga` and Codex; it is advisory and not part of `Pruebas`. The repo is private, so Actions minutes are limited: keep jobs cached and skip what a change cannot affect.

## Payload rules

| Rule | Why |
|---|---|
| Every premium collection and field has `access` functions that check the member's entitlement on the server | Gated content must never reach a client that is not entitled |
| Never hide gated content with CSS or client logic | Hidden content still ships in the HTML and the React Server Components payload |
| The local API skips access control unless told otherwise. When rendering for a visitor, pass `overrideAccess: false` and the current `user` | The default (`overrideAccess: true`) is for trusted server jobs only, such as the import |
| Use the local API (`getPayload`) from server code; never call our own REST API from the server | One process, no HTTP round trip, typed results |
| Every schema change ships with a migration (`pnpm migrate:create <name>`, applied with `pnpm migrate`), committed and reviewed. Schema push is for local development only | Production applies migrations; nothing changes the schema by hand |
| Paywalled pages emit Google's paywalled-content structured data | The plan requires it for search |
| Premium themes (Amakna, Bonta, Brâkmar, Ocre) are an entitlement: the server renders a premium `data-theme` only when the member's entitlement allows it, and saving one is rejected otherwise. A theme value from the client, a cookie or `localStorage` is never trusted on its own. Arcano is the free default | Hiding a premium theme behind a client switch would hand it to everyone |
| Premium view modes, such as "Modo compacto" on quest pages, are entitlements like any other: the server picks the layout, and the free view is the full guide | A client-side toggle would hand the feature to everyone |
| Drafts, versions and live preview stay on for editorial collections | Torre edits in the panel (plan section 5) |
| Derived checklist data is computed in TypeScript at publish time (`src/lib/derive/`), from relationships, not from parsing text | It replaces the old Python pipeline |
| Game data (quests, items, monsters from DofusDB) is read-only in the panel and refreshed by a script | Torre picks it through relationship fields |

## Next rules

| Rule | Detail |
|---|---|
| Server components by default | `"use client"` only for islands: the checklist app, search dialog, theme switch, member menu, dialogs |
| No client JavaScript on guide pages beyond the shell | Lighthouse CI enforces the 150 KB budget |
| Fetch data on the server | In server components or route handlers through the local API; no client-side fetching of content |
| Entitlement checks happen per request on the server | A premium block is not rendered, and not serialized, for a visitor without the entitlement |
| Revalidate on publish | Payload `afterChange` hooks call `revalidateTag`/`revalidatePath` for what changed (planned) |
| Theme and mode | The server renders `data-theme` on `<html>` from the member's saved setting, checked against the entitlement; anyone without it gets `arcano`. The mode (`data-mode`, dark or light) is free: a cookie plus `localStorage`, and an inline `<head>` script sets the mode only before first paint (default `dark`); `<html suppressHydrationWarning>` |
| Fonts through `next/font/google` | Barlow, Barlow Condensed, Lilita One; self-hosted, no layout shift |

## Members and progress

- Anonymous by default: checklists work without an account and save in the browser. Every `localStorage` access is wrapped in `try/catch`.
- One global progress set per member, in our own Postgres tables (Drizzle), not in Payload collections. Quests and quest objectives are keyed by DofusDB quest id, owned items by DofusDB item id, steps by their stable step UUID. Never key progress by step number or position.
- Checklists are views over that set: finishing a quest in one checklist marks it everywhere.
- Each entry carries `updatedAt`; the server merges by latest timestamp; the client queues writes offline and flushes on reconnect.
- Inference rules (prerequisites implied done, completed-by) run once, on the server, over the global set.
- First sign-in offers to import the old keys (`silvestre:*`, `hielos:*`, `global:*`, `dofus-checklists:shared`) and shows what it found before writing anything. The mapping from old step numbers to step UUIDs lives with the import code.
- Members can export and delete their data.

## Media

- Images are converted offline before the import into fixed AVIF and WebP variants and uploaded to R2 with the originals. The app never optimizes images on request; no Next image optimization, no Vercel image billing.
- Every media record keeps its alt text, credits, width and height, the variant keys and the original Squarespace URL.
- Real game art only (see `DESIGN.md`). Nothing loads from DofusDB or Ankama at runtime.

## Secrets and environment

- `.env.example` lists every variable with an empty or dummy value and a comment. Add a line there in the same change that reads a new variable.
- Never commit secrets. `.env*` is git-ignored except `.env.example`.
- Server-only variables never get the `NEXT_PUBLIC_` prefix.
- Read today: `DATABASE_URL`, `PAYLOAD_SECRET`, `NEXT_PUBLIC_SITE_URL`, `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_REGION`, `MEDIA_BASE_URL`, `GIT_COMMIT_SHA` (after Railway's `RAILWAY_GIT_COMMIT_SHA`). The smoke tests read `SMOKE_BASE_URL`, `SMOKE_BASIC_AUTH_USER` and `SMOKE_BASIC_AUTH_PASSWORD`.
- Planned: `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `EMAIL_API_KEY`, and the payment keys in phase 5.
