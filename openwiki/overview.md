# Project overview

ta-web is the new torrentearcano.com: Torre's Dofus quest guides, achievements, classes, Dofus guides and checklists, with member accounts, per-member progress and premium features. It replaces the current Squarespace site and the checklist embeds served from the separate `silvestre-checklist` repo.

The site, the CMS panel and the UI copy are in Spanish. The repo's docs are in English.

## Stack

| Layer | In use today | Planned |
|---|---|---|
| App | Next.js 16 App Router, React 19, TypeScript, server components | |
| CMS | Payload CMS 3, inside the Next app | More editorial collections, globals, more guide blocks |
| Database | Postgres through Payload's adapter; Neon when deployed, embedded Postgres 17 locally | Drizzle tables for member progress |
| Media | Cloudflare R2 through `@payloadcms/storage-s3`, local disk as fallback; AVIF/WebP sizes generated by Payload on upload | |
| Styles | Tailwind v4 with the tokens from `DESIGN.md` | |
| Members | | Better Auth (Google, Discord, magic link) |
| Search | Name search over a JSON index of published quest guides, achievement pages and metalogros (`GET /api/search/guides`), shared by the header dialog and the home page | Postgres full text (`spanish` plus `unaccent`) |
| Hosting | One Node container per environment on Railway (`dev`, `production`) | |
| Errors | Sentry, server only | |

Runtime: Node 24 (`>=24.22.1 <25`) and pnpm 11, pinned in `package.json`.

## What exists today

The skeleton is done, quest guides and achievement pages are live in the app, and member features are not built yet.

- **Public site**: a site-wide header (the Sello lockup, a menu panel per section, the search dialog and the dark/light mode switch) and footer; the home page with its hero search for quests and achievements; quest guide pages at `/<slug>` in the v5 single-column layout (breadcrumb to the achievement, quest giver NPC, summary columns with the rewards bag, steps separated by a line, fight blocks and the next quest card); achievement pages at the same `/<slug>`; and the metalogros index at `/metalogros`. Guides and achievement pages have draft preview from the panel and revalidate on save. Pages the app does not have yet (Dofus guides, checklists, classes, dungeons, legal) are linked on the legacy Squarespace site; quest and achievement links never go there. Fonts are Montserrat and Lilita One. See [Home page](frontend/home-page.md), [Site header, footer and search](frontend/site-shell-and-search.md), [Public quest guide page](frontend/guide-page.md), [Achievement page](achievements/achievement-page.md), [Metalogros index](achievements/metalogros-index.md), [Styles, tokens and site shell](frontend/styles-and-shell.md) and [Theme and mode](frontend/theme-and-mode.md).
- **Design system**: the generic components (`src/components/ui/`) and the quest guide components (`src/components/game/`) from `DESIGN.md`, with one client island on guide and achievement pages, `PageEnhancements`, that copies coordinates, plays videos on click, opens images fullscreen and opens and closes the rewards bag. The guide page renders them, and `/sistema` shows every component in the five themes and both modes; it answers 404 in production. See [Design system components](frontend/design-system-components.md) and [Component catalog (/sistema)](frontend/component-catalog.md).
- **CMS**: Payload with eleven collections: `users` (panel accounts, locked for ten minutes after five failed logins), `media`; `quests`, `items`, `monsters`, `npcs`, `achievements` and `achievement-categories` (read-only DofusDB game data); and Torre's editorial collections with drafts and versions, readable by the public only once published: `quest-guides`, `achievement-pages` and `achievement-groups` (metalogros). Spanish admin UI and a single `es` locale. Guides, achievement pages and metalogros share one slug space at the root. A guide starts from its DofusDB quest, one per guide: picking it fills the empty title, slug, SEO fields and summary (prerequisites, the "Necesitarás" item list, rewards, start NPC and coordinates), live in the panel form and again on save, and never overwrites what is already written. Guide bodies are built from rich text, image, video (YouTube only), callout, fight and step blocks. Achievement pages and metalogros fill their empty fields from their DofusDB record the same way, with a note under each field comparing it with DofusDB, and their state (Publicada or En preparación) is Torre's. See [Writing a quest guide](cms/guide-authoring.md), [Achievement data model](achievements/achievement-data.md), [Payload CMS configuration](cms/payload-config.md), [Collections and access](cms/collections.md) and [Guide body blocks](cms/blocks.md).
- **Data**: fourteen committed migrations; schema push only under `next dev`. See [Database and migrations](data/database.md).
- **Game data**: `pnpm data:quests` copies every quest from the public DofusDB API into `quests`, the whole DofusDB monster and item catalogs into `monsters` and `items`, so a guide can name any of them, every achievement category and the achievements under Misiones and Eventos, and the quest-giving NPCs into `npcs`. It imports into `media` once the NPC renders, the achievement icons and the images of the items and monsters some page shows, and creates the missing metalogros and achievement pages «En preparación»; idempotently and without deleting anything. Each quest stores its zone, its achievement and position in it, its rewards for a level-200 character (XP and the XP at the optimal level, kamas, items, emote, spell, title and job IDs) and its needs (items, monsters, whether you walk new maps). See [DofusDB game data refresh](data/dofusdb-refresh.md).
- **Squarespace import**: `scripts/import/` turns a cached Squarespace page into a quest guide draft (summary, start NPC, an introduction, steps and a closing, callouts and Torre's recommendations) and lists what it could not convert. `pnpm import:guides` loads them into `quest-guides` as drafts, with each image stored once in `media` and the guide's DofusDB quest linked when the page names exactly one that is already in `quests`; the summary gaps are filled from DofusDB as on save, so re-running it changes only what changed and never publishes. Five demo guides are covered by tests. `pnpm guides:backfill` brings guides imported earlier up to the current importer (closing sentence, fight blocks), and `pnpm import:achievements` copies Torre's metalogros index (order, names, slugs, states) onto the metalogros and achievement pages, with `pnpm fix:achievements` for targeted corrections afterwards. See [Squarespace import](data/squarespace-import.md) and [Importing Torre's achievement pages](data/achievements-import.md).
- **Media**: R2 or disk, chosen by environment. See [Media storage](media/storage.md).
- **Operations**: `GET /api/health`, the search index at `GET /api/search/guides`, the panel's `GET /api/dofusdb-values/:source/:id`, a public dev environment that is never indexed, server-side Sentry, Railway infrastructure as code, and GitHub workflows for CI, dev smoke tests and production releases. See the operations pages.
- **Quality**: unit, integration, E2E (including axe WCAG 2.2 AA on every public page type), dev environment and smoke suites; Lighthouse CI performance budgets on the home page, a seeded guide, a seeded achievement page and `/metalogros`; lint, format, types and dependency audit in CI; git hooks for formatting, linting, AI review and commit messages. See [Test suites](testing/test-suites.md) and [Performance budgets](testing/performance-budgets.md).

## What is planned

AGENTS.md describes the target layout and rules. Not yet in the code:

- The other editorial collections: Dofus guides, checklists, classes, dungeons, pages (`src/collections/`).
- `src/globals/` (navigation, socials, Ko-fi, Twitch card, announcement bar), and the dialogue block in `src/blocks/`.
- Members with Better Auth, per-member progress in Drizzle tables, entitlement checks, premium themes and view modes.
- The rest of the Squarespace import (`scripts/import/`): the review queue and the other page types.
- Postgres full-text search, the Twitch live state, and the derived checklist data.

When a rule names a path that does not exist yet, create it with that name.

## How the pieces connect

```
Browser ──▶ Railway container (Node 24)
              └─ Next.js
                   ├─ proxy.ts ─ noindex header (dev only)
                   ├─ (frontend) routes ─ server components ─ Payload local API
                   ├─ (payload) routes ─ /admin, REST, GraphQL, /api/health
                   └─ instrumentation ─ Sentry
              ├──▶ Neon Postgres (pooled URL; direct URL for migrations)
              └──▶ Cloudflare R2 (uploads; public CDN URLs)
```

One build serves both environments. Everything that differs between dev and production is read from environment variables at runtime. See [Request pipeline](architecture/request-pipeline.md) and [Environment configuration](architecture/configuration.md).
